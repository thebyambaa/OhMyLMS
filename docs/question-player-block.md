# Question Player block

Insert **OhMyLMS Question Player** in a WordPress page, post or lesson. Choose specific approved bank questions and arrange them in order, or choose skills and a maximum question count. Random runs draw a new set from the selected skills and their subskills, without duplicate questions; a smaller pool uses all available questions. Each launch freezes the selected approved versions, option order and template numbers for that run.

**Grade responses** defaults on. Graded student responses save item-level grade events and show the score at submission. Turn grading off for an ungraded activity: responses and completion are saved, but no correctness, score, grade events or skill evidence are produced. **Count toward skill performance** defaults off and requires grading. Enabling it sends grades through the existing frozen skill-mapping/evidence pipeline and Khan assessment rules. Disabling it prevents evidence-outbox creation, including during evidence rebuilds. These activities do not complete lessons or alter a course quiz's attempt history.

The player uses the same immutable snapshots, renderers, option tokens, math controls, visual widgets, answer validators and graders as the quiz player. It offers one question per page, Previous/Next navigation, required-answer checks, submission results and Play again. Playing again draws another random set. Browser-session resume retains the issued set and completed results; unfinished answers currently need to be re-entered after a reload.

Students must log in. Only approved, non-exam, automatically marked questions are eligible; teacher-marked responses continue to use formal quizzes and their review workflow. A placement's author must have permission to use each question, and course-bank access is checked for the learner. Author previews can try questions and scores, but write no grade events or skill evidence. Authoring the block never starts a run.

The saved post is authoritative for the configuration. A launch cannot supply its own question IDs, grading switch or performance policy. Sessions are owner-bound, linked to the parent post/configuration and rechecked on resume/submission. Changed configurations require a new run. Submission locks the session row, commits all answers and grades in one transaction, and returns the existing result on retry. Multiple blocks keep independent sessions.

Source: `assets/src/blocks/question-player/` (Gutenberg), `assets/interactivity/question-player.js` (learner UI), `includes/Blocks/QuestionPlayerBlock.php` (placement/access/REST) and `includes/Practice/QuestionPlayer.php` (frozen runs). Runs reuse the existing practice-session/item tables under the separate `question-player` mode; ordinary practice endpoints reject this mode. Grade events retain their default evidence behavior unless a caller explicitly supplies `record_evidence=false`.

Verification: `tests/js/question-player-block.test.mjs` checks reference-only storage, selection ordering and outcome-switch behavior. `tests/php/question-player-integration.php` exercises real REST permissions, ownership, required answers, grading-only/ungraded/tracked modes, instructor isolation, idempotent submission, random-pool bounds and secure-question exclusion. Its transaction rolls back successful and failed fixture runs.

Which questions a player accepts is decided by `Assessment\DeliveryPolicy` (approved, not exam-only, not teacher-marked), the same rule the inline check uses. In the editor the player is the **From skills** and **Pick from bank** states of the one **OhMyLMS Question** block (use its source switch); it has no separate inserter entry, and its Play mode control still chooses an activity or game. Exam kinds do not offer it. See [assessment profiles](ASSESSMENT-PROFILES.md).

**Pick from bank** and **From skills** open a dialog for searching, adding and removing selections. Bank selections can be reordered; the skills dialog also sets the maximum question count. Changes apply immediately; use **Done**, Escape or the close button to return to the block. Click either source again, or **Edit selection**, to reopen it. Empty players open the selector on insertion.
