# Native Gutenberg quiz authoring

Gutenberg is now the default quiz and standalone question editor. **Add Quiz** and bank authoring actions open WordPress’s actual editor. See [the current authoring guide](GUTENBERG-AUTHORING.md); the notes below describe the original shared-question integration and its verification history.

Use core headings, paragraphs, images and layout blocks for the introduction. Insert **OhMyLMS Multiple Choice** and use its Question type dropdown for multiple choice, checkboxes, reorder, short answer or long answer in quizzes. Reorder items are authored in their correct order, using drag or move-up/move-down controls; existing order-based grading is retained. Short and long answers retain the existing `short-text` and `long-text` contracts and teacher grading; the card shows a disabled learner response field while authoring. The quiz Question type dropdown also includes Number line, Shade a model, Count with blocks, Set the clock, Make an amount, Fill to a level, Build a chart, Build on a grid, Labeling, Hotspot and Draw. These use the existing visual configuration controls, private answer settings and learner renderers. Complete visual questions autosave without choice options; labeling and hotspot require an image. Draw responses await teacher review. Native lesson practice retains the two choice modes because written responses require teacher review. **Multiple correct answers** preserves option identities. Complete question edits save automatically after a short pause, then Gutenberg saves the quiz. Pending or invalid question edits lock post saving. Native block movement determines question order. The original form remains behind the temporary rollback setting; native extension adapters preserve supported custom question editors.

The native question card follows the supplied form-card structure: prompt and selection-type dropdown in the header, simple option rows, then duplicate/remove actions, Required and a three-dot settings menu. The prompt and answers have no Format dropdown. Existing equations remain editable through their MathLive controls and the field keyboard shortcut. The card has no separate Preview question, Save question, status or Help footer; the editor-level Preview quiz action remains available. The settings menu contains shuffle, score, hint, explanation and partial grading. Lesson approval remains an explicit action in that menu.

Autosave writes complete questions through the existing bank API. Saves are serialized, incomplete questions wait for a valid prompt/options/key, and errors stop retries until an edit or explicit Retry. In-flight responses reconcile option IDs without discarding newer local edits or changing input keys. A non-private `authoringRevision` counter on the reference makes the native document dirty after a bank save; it does not select a question version or replace frozen quiz revisions. Gutenberg's Save remains the post/revision publishing action.

## Storage and delivery

Question blocks store only question ID, UUID and delivery mode. Prompts, answers and keys remain private in the versioned question bank, with capability checks and modified-version conflict protection. Native REST saves validate references, reject duplicate or missing questions, normalize attributes and transactionally synchronize quiz relationships. Publishing uses existing assessment revision rules. Removing a placement preserves its bank question and frozen revisions.

Core blocks become the quiz introduction; questions use the existing quiz player in placement order. They do not start lesson practice sessions. Other formats remain movable reference blocks and use their existing form editors. The card's Duplicate question action creates an independent bank question and inserts its reference. Gutenberg's generic Duplicate command still copies a reference; duplicate references in one quiz are rejected.

Native lessons use the same block with approved-version selection, signed practice tokens and server grading. Lesson practice and quiz attempts remain separate. MathLive statement and option controls retain the equation contract and use the field's document for iframe selection and caret handling.
