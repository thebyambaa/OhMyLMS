## Workflow

Create a Roadmap from Curriculum by checking up to ten source syllabuses and saving its name. Creation opens the syllabus editor, even when the selected sources have no mapped shared skills yet. Use the existing syllabus outline to rename the Roadmap, organize its folders and steps, edit skills and attach learning resources.

**Roadmap sources** is on the syllabus home. Search and select up to ten syllabuses or roadmaps, then click **Save roadmap sources**. This explicit, revision-checked save retains all current folder assignments and skill order. It never automatically adds steps from new sources or removes existing connections. Source drafts survive browser-session navigation; **Discard source changes** returns to the saved selection. Save or discard visible source edits before opening the visual editor. Sources cannot include the Roadmap itself.

**Open visual editor**, beside **Skills** in the top bar, opens the full-screen node canvas. Search the paged shared-skill library or choose a saved source syllabus to find objectives by their complete text, topic or unmapped status. Selecting a shared skill loads its actual links across source pages. The canvas displays eight connections at a time; Coverage reports links by source and version.

**New shared skill** uses the existing skill form and remembers the Roadmap association. Creation does not automatically insert a new ordered step or publish a course. Choose source objectives and explicitly save each connection. Drag card headers, use arrow keys or directional buttons to arrange the view. Card positions do not change learning order, prerequisites or assessment rules.

Select a connection to review its relationship and note. **Change connected skill** previews a replacement while the original remains saved. **Save connection** uses a guarded single-row update that preserves the mapping ID. Stale revisions, duplicate pairs and shared-skill chains are rejected. **Undo edits** and **Discard proposal** apply to unsaved connection edits. Removal requires explicit review and preserves both skill records and historical evidence. Closing a dirty editor offers to keep its session draft; reopening recovers it.

**Edit complete group** opens a focused modal listing every required objective, with relationship and note controls and explicit whole-group removal. Group members are never individually reconnected. Closing with unsaved group edits requires an explicit discard choice.

Relationships remain directional: **Equivalent** pools assessment evidence; **Source is broader**, **Source is narrower** and **Related** are descriptive only. **Required together** is a combined-coverage group requiring at least two objectives from one syllabus. Its purple connections describe joint coverage without calculating mastery, pooling evidence or inheriting resources. Matching names never create a relationship.

The additive `POST /ohmylms/v1/syllabus-comparison/mapping/reconnect` endpoint requires integer `old_specific_id`, `specific_id`, `shared_id` and `source_id`, an individual `relation`, optional `note`, and the original pair's `expected_revision`. The replacement must belong to the supplied source. The `MappingReconnect.php` filename follows the existing PSR-4 class mapping; its narrow filename exception preserves that autoloading contract.

Mapping coverage, direct mastery and pooled shared mastery remain separate. Related mappings contribute no pooled evidence or automatic resource inheritance. Unassessed skills are not failed mastery. Learner visibility, assessment contracts, resource ownership and publication checks retain their existing rules.

## REST and MCP

The additive administrator API lives under `/ohmylms/v1/syllabus-comparison`: `syllabuses`, `objectives/{id}`, `shared-skills`, `shared-skills/{id}`, `shared-skills/save`, `shared-skills/{id}/content`, `mapping`, `mapping/remove`, `roadmaps`, `configuration`, and `audit/{student_id}`. `/me/subject-skills` and `/syllabus-comparison/audit` return only the authenticated account's plans. WordPress REST cookie authentication requires its standard nonce. MCP bearer authentication retains the issuing administrator's capability checks and dispatches through the same REST callbacks.

The MCP add-on adds thirteen tools: `list_syllabuses`, `list_syllabus_objectives`, `list_shared_skills`, `get_shared_skill`, `save_shared_skill`, `save_skill_mapping`, `remove_skill_mapping`, `configure_subject_syllabuses`, `list_shared_skill_content`, `connect_shared_skill_content`, `create_shared_skill_roadmap`, `audit_my_study_plans`, and `audit_student_study_plans`. Native Abilities schemas reject unknown arguments. Tools have accurate read/write, destructive and idempotent annotations. The original nine content-read tools retain their names and behavior.

Shared-skill edits require `expected_revision`. Mapping creation requires an empty revision; edits/removal require the current revision from an objective page. Revisions cover content rather than second-resolution timestamps. Stale edits return HTTP 409. Mapping batches save one pair at a time and retain failed/unsaved selections; successful pairs remain saved. Reload proposal revisions and review before retrying a conflict.

Trusted extensions may add content types through `ohmylms_shared_skill_content_types`, a map of resource kind to registered post type. Content writes require edit permission on the specified post and append/remove only this skill's term relationship. Published learner resource links contain titles and URLs, never draft content or quiz answers; destination access rules remain in force. Resource lists are bounded to 20 per kind/page.

## Initial mathematics sources

The existing local data was inspected: syllabus **5**, `0580 IGCSE`, has 125 objectives, and syllabus **8**, `Digital SAT Math`, has 93. Neither stored a syllabus version at inspection; no mappings existed. These imported texts and codes are preserved. Cambridge 0580 **2028–2030** is the user's selected target, not an automatic certification that older imported descriptions already match it. The comparison visibly flags missing versions. Review/revise the syllabus before assigning its version or publishing a study plan; automatic matching and unreviewed syllabus migration are not implemented.

Official references: [Cambridge 0580 2028–2030, version 2](https://www.cambridgeinternational.org/Images/745681-2028-2030-syllabus.pdf), [Cambridge syllabus update](https://www.cambridgeinternational.org/Images/763300-2028-2030-syllabus-update.pdf), and [College Board Math content](https://satsuite.collegeboard.org/sat/whats-on-the-test/math/types). Digital SAT's imported fine-grained codes are local codes; they are not represented as official College Board objective identifiers. Mongolia or other curricula can be added through the existing syllabus import workflow.

## Compatibility and limits

No existing public route, hook, assessment field, question extension or taxonomy identity was renamed. Existing mapping callers may omit the new expected revision; the new comparison and MCP flows always supply it. New class files retain namespace-matching case for the repository's existing PSR-4 Composer mapping; only the filename sniff is narrowly excepted at the opening line. All other coding checks remain active. MySQL advisory lock calls are necessarily uncached; bounded taxonomy/meta queries still receive performance warnings from WPCS.

Structural splitting/merging, automatic mapping, automatic exam-credit transfer, readiness scores and personalized per-student plan authoring remain outside this release. Profile labels currently define administrator-selected source sets; audits are read-only. Session drafts last for the browser session. Publishing remains an explicit syllabus/course action; configuring a profile does not publish or enroll it.
